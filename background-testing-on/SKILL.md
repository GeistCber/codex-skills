# 开启后台测试模式

独立入口，仅在用户明确要求执行开启时修改状态。引用、示例、比较开关形式或查询含义不代表开启请求。

用编辑工具检查 `C:\Users\Laptop\.codex\config.toml` 中路径为 `C:\Users\Laptop\.codex\skills\background-testing\SKILL.md` 的 `[[skills.config]]` 项，把 `enabled` 设为 `true`；无匹配项时添加一项，保留其他设置。匹配路径忽略 Windows 大小写与分隔符差异，不能制造重复项；若已有重复项，先核对并仅合并该主技能的配置。禁止用 Python/Shell 重写配置。

回读确认后，立即执行下列流程。已经开启时也同样检查，不仅回复“已开启”，不要求用户再说继续。

1. **恢复目标。** 根据当前会话最近的业务请求、实际路径和完成报告确定项目；必要时读取较早记录。cwd、技能安装目录或参考示例不能单独作为目标。只在仍有关键歧义时集中询问，不扫描无关项目。
2. **加载并检查。** 读取[主技能](../background-testing/SKILL.md)，按适用规则核对已有后台入口、当前改动和验证证据。先匹配输入/代码/测试配置，有有效结果时明确复用历史证据；缺失或失效时执行必要后台检查，不无故重跑全部测试。
3. **推进授权内工作。** 当前项目仍有已授权的实现或验证工作时，按主技能完成；若只有开启请求，不重新实现已完成业务。不启动鼠标键盘或抢焦点窗口作为默认补测，单列桌面未测项，沿用用户已有的具体授权。用户已暂停或取消的任务不恢复。
4. **报告并保持。** 说明模式已开启、当前项目检查结果和未测范围；没有明确项目时说明开关已开启、尚无可定位项目，后续相关任务再执行，不猜测业务路径。设置持续生效直到用户关闭，不建立后台服务、钩子或定时任务，不承诺无执行机会也会自唤醒。

本开关只控制后台测试策略，不改变 Git 同步、模型、权限或其他技能。开启不等于授权接管办公桌面。
