# 开启 Git 同步

本技能是独立开关入口，主技能被禁用时仍可使用。仅在用户明确要求执行开启时操作；引用或询问命令含义不应改变状态。

用编辑工具检查并修改`C:\Users\Laptop\.codex\config.toml`中路径为`C:\Users\Laptop\.codex\skills\github-sync-on-complete\SKILL.md`的`[[skills.config]]`项，将`enabled`设为`true`；不存在时添加一个配置项，不制造重复项，保留其他配置。不要用Python或Shell脚本重写配置文件。

回读并验证状态后，立即继续以下流程，不能只回复“Git同步已开启”就结束，也不能要求用户再发一句“继续”或重复项目描述。已经开启时同样立即检查。

1. **恢复当前项目。** 从当前会话最近的业务请求、实际读写路径、完成报告和验证结果确定目标项目。必要时读取本会话较早记录。当前工作目录、示例截图中的项目名和历史上其他项目都不能单独作为目标依据。上下文已能确定项目时不要再问项目在哪里；只有仍无法定位或多个目标确实有歧义时，集中询问缺失信息，不扫描无关项目。
2. **立即检查。** 读取[主技能](../github-sync-on-complete/SKILL.md)，按其中“完成节点与选择”检查该项目的实际改动、必要验证证据、仓库、分支、远程和未推送提交。历史完成报告可作为线索；核对当前文件和已有验证是否对应，只有缺失或改动使验证失效时才补必要检查，不重新实现业务。
3. **推进到可执行节点。** 项目已完成并验证通过且有待同步内容时，本轮直接弹出“上传到GitHub / 暂不上传”，写明目标和范围；不先用完成答复结束本轮。收到上传选择后按主技能自动提交、推送和核验。用户已明确授权本次上传时直接执行；已选择暂不上传的同一节点不重复询问。项目仍有当前已授权且可继续的工作时，继续完成和验证后再检查同步；用户已暂停或取消的工作不擅自恢复。没有待同步内容时说明已同步；缺少必要信息时准确说明缺什么。
4. **保持开启。** 后续任务继续按全局完成规则执行，直到用户关闭。开启只自动执行上下文恢复、检查和上传询问，并不提前授权实际上传；不上传本机开关、全局配置或凭据。本技能不是后台监控器，不能声称会在没有新任务或对话执行机会时自行唤醒。
