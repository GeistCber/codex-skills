前半段由 AutoCAD 完成

可使用 accoreconsole.exe 和 .scr 加载插件，程序选中目标后调用注册命令。若直接调用规划器或写图器，只能标为局部验证。依赖桌面 UI 的入口不能强行换成另一入口而宣称通过。

原生打印需核对 PDF 设备、范围、纸张、比例、打印样式及目标对象可打印性。保留原始 PDF，检查没有漏尺、刻度缺失、遮挡或裁断。

后半段由转换脚本完成

scripts/render_native_pdf.py 只读取已有 PDF 并生成 PNG；不启动 CAD、不标注、不补画。依赖 PyMuPDF 与 Pillow，使用已有可用 Python 环境。

参数作用
--page 1选择页，默认第 1 页
--scale 4栅格化倍数，默认 4
--padding 30裁白边后留边，默认 30 像素
--no-crop保留整页便于核对
python <技能目录>/scripts/render_native_pdf.py result.pdf result.png --scale 4
替代的范围： 白底图优先承担几何与打印外观展示。屏幕显示和操作路径仍由对应桌面证据核对；用户明确要求实操时继续实操。PDF 转图只检查图片化能力，不能被算作新一轮 CAD 功能验证。

验证要分层，失败要回到正确阶段

方法能证明什么不能据此声称
算法测试 / 构建受测计算与程序集配置通过CAD 已加载、视觉与交互通过
原生无界面宿主实际执行过的 DWG/API/命令、写入保存与导出VS F5、鼠标选择、焦点、按钮通过
结果 DWG 原生打印该结果文件的几何与打印外观屏幕和打印逐像素相同、所有入口与图纸都通过
桌面实操 / VS F5实际执行过的启动及用户操作路径未执行的其他路径、布局或版本通过

尺寸与实体

相同输入、宿主版本、DLL、命令、选区、参数及相关状态下，两种运行方式的实体结果应一致。比较端点、尺线位置、数值、类型、样式；不要求 PNG 像素相同。

打印与屏幕

字体替换、注释可见性、CTB/STB、线宽、图层打印和裁剪可能导致差异。屏幕还可能未重生成或存在显卡显示问题，需在目标宿主核对。

启动与操作

字体弹窗、旧 DLL、焦点、鼠标选区、纸/模型空间、取消和按钮事件属于交互。原生成功与桌面卡住可以同时存在，应分别报告。

本次最小有效覆盖：按改动选择

几何变化：独立预期、受影响的正反/旋转/镜像、邻接与空气边界。
读取分类：实体来源、块变换、可见性、属性继承；仅覆盖本项目声明支持的对象。
代码结果：实际生产入口、完整对象、测量值与尺线；重复替换或保存重开按功能需要选择。
布局视口：空间映射、旋转/裁剪、标注可见性与落点。
版本：输入、配置、实际加载程序集与证据对应；旧宿主不能代表新 DLL。
文档任务：只检查来源、链接和规则一致性，不启动业务桌面测试。

差异处理顺序

  1. 保留失败现场及输入、代码版本。
  2. 区分规则缺口、实现错误、读取/坐标问题、真实材料间隙和宿主显示差异。
  3. 规则缺口回设计；实现错误按已批准规则修复；数据或显示问题回到相应入口。
  4. 修复失败路径并覆盖直接受影响行为；预期若改变，需要独立依据。
  5. 未执行部分明确未测，不能把原生通过改名为实操通过，也不能靠放宽阈值“消灭”失败。

等待选择时可以继续不依赖该答案的已授权工作。技能选用本身不会授予桌面接管或上传权限。

通用保护要求

  • 源图、用户其他尺寸和正在使用的 CAD/VS 实例受到保护；核对进程与文档身份后仅操作授权目标。
  • 测试使用保全副本；构建前检查示例复制规则，避免覆盖用户改过的 Debug/Examples 图纸。
  • 源码、配置、说明用编辑工具修改；构建、导出与测试结果由相应工具生成。
  • 技能不固化项目材料、颜色、数值和算法，不为套流程重构整个项目。

维护时要防止哪些误用
  • 把可行性讨论当成生产实施授权；已批准方案反复确认。
  • 把测试专用提案悄悄接到正式入口；用诊断图或生产结果替代独立设计预期。
  • 把原生宿主、打印图或算法检查改称 F5/桌面实操通过。
  • 把 GoodMe 材料、颜色和尺寸常量搬到其他项目。
  • 忽略关闭的测试开关、现有未决分支，或覆盖用户改过的示例 DWG。
  • 纯技能/文档整理却启动 CAD；普通编译、环境、完整验收或上传却强套此流程。
  • 只有计算预览就宣称闭环完成，或单项成功就宣称全插件完成。
