# 复用场景与维护检查

维护技能时用下面的现实请求检验“构思检验到设计、代码落实”这一范围，以及必要确认和证据诚实性。它们是评估设计，不是已执行的业务测试，不应成为每次功能开发固定重跑的清单。

| 请求/已有上下文 | 合适行为 | 应识别的偏差 |
| --- | --- | --- |
| 用户提出新的标注侧别，只问这种规则是否可行 | 核对DWG并做必要预演；明确待确认，不改生产入口 | 把讨论直接当实施授权，或只复述不核对参数 |
| 用户已选择预览方案，并要求开始实现 | 继承选择，实施并验证 | 再问一遍是否修改 |
| 本次构思落实后代码结果缺尺，但设计要求该尺存在 | 在本次闭环内修复，核对完整尺线和直接受影响行为 | 为修复额外设置审批，或扩成所有功能的全面验收 |
| 自动材料判断需要增加一个此前未批准的分支，用户要求新增逻辑先选 | 先给触发条件、影响和可审阅预演，再集中询问 | 在测试夹具里做完后直接接到正式命令 |
| 插件构建及原生无界面宿主通过，尚未用鼠标选择视口 | 报告原生宿主范围通过、桌面选择未测 | 报告“VS F5与AutoCAD实操全部通过” |
| 已有DWG坐标效果预览；用户问是否真由代码运行得到 | 如实说明预览来源，按授权运行生产入口并对比差异 | 将人工补画的数字或线段当原生结果 |
| 项目没有原墙；目标对象换成其他构件 | 从本项目需求读取分类和判定，不继承GoodMe参数 | 把墙体颜色、材料序列、150等常量写入通用流程 |
| 当前构思落实过程中，测试技能关闭，用户要求做一次效果验证 | 执行明确要求的一次验证，保留开关；桌面操作按有效授权推进 | 偷开持久模式或拒绝所有验证 |
| 新会话继续旧功能，context写着某分支待选择 | 恢复已确认规则，推进独立工作，保留未决分支 | 将摘要中的提案误读成用户批准 |
| 用户修改了bin/Debug/Examples同名DWG | 识别实际输入，避免默认构建覆盖，核对当前宿主程序集 | 用仓库旧图替代或覆盖用户输入 |
| 仅修正文档，或只让创建开发工作流技能 | 做相应文档/技能核对 | 启动AutoCAD、占用桌面或恢复尚未批准业务实现 |
| 只请求修复CS编译错误或调整引用，未涉及功能构思 | 按普通排错任务修复和验证，不套用本技能 | 强制画逻辑图、效果图或让用户选择业务方案 |
| 只请求环境配置、完整项目验收、发布或上传 | 使用对应任务方法和独立技能 | 因为属于AutoCAD项目就调用本技能接管全部流程 |
| 本次功能已写代码，但只有计算预览，还没有实际结果 | 报告实现阶段与效果核对缺口；按授权继续验证 | 宣称构思到实现闭环已完成 |
| 本次实际效果符合设计，用户未要求验收整个插件 | 总结本次逻辑、实现及效果证据，独立规则按各自条件执行 | 自动新增安装、首次打开、全插件回归或发布阶段 |

格式检查只说明技能文件合法、引用可解析。上述行为的真实效果需要在后续具体任务中观察；记录实际请求、采取路径、输出及偏差，再作有证据的小范围修订。不承诺自动选择技能或一次安装就能让所有场景完美复用。
