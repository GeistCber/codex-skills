# 桌面控制与生命周期

## 两种独立状态

持久 `enabled` 只控制后续是否自动采用本方法，沿用既有 TOML 和 on/off 入口。单次运行另记 `phase` 和 `control`，不是第二个启用开关。开启不能恢复被取消的任务，关闭不能冒称终止了已有进程；暂停运行也不自动关闭持久开关。

| phase | 工作 | 默认 control |
|---|---|---|
| inventory | 盘点需求、输入和资源 | background |
| planning | 覆盖清单、独立预期和桌面约定 | background |
| preflight | 必要构建、加载和测试前提检查 | background |
| desktop | 有界的真实界面全流程测试 | desktop（接管后） |
| supplement | 数值核对、脚本回归与原因定位 | background |
| fixing | 修复问题；必要时回到实操 | background |
| reporting | 核验报告、覆盖缺口与证据 | released |
| paused / finished | 安全停止点 / 本轮结束 | paused / released |

`control` 可取 background、desktop、paused、released。阶段和执行方式分开记录，例如 planning 等待桌面约定时仍可 background；desktop 被用户打断后是 paused。进入下一阶段前先通知，再在 `events` 记下实际时间、阶段、control 和已发送的通知摘要。记录不能伪造用户已收到通知或已授权。

## 接管约定

第一次需要桌面前，一次说明目标应用/版本、测试副本、要测的业务批次、共享桌面还是隔离环境、预计占用规模（可给大致范围，不虚报 ETA）、停止方式。沿用同一会话中已明确的具体授权，不逐次确认。

- 用户明确要求真实点击/完整实操且应用和范围清楚时，通常已有授权；通知批次后执行。泛泛的“开启技能”或“做测试”不能自动扩展为任意应用的全局键鼠控制。
- 没有授权时，用一次集中输入问题确认“现在使用桌面 / 先完成后台并等待 / 已有独立测试环境”；等待时继续独立的准备与脚本工作。沉默或超时不等于批准。
- 已约定的批次之间只需通知进度和后续操作；切换应用、改动用户原文件或扩大桌面范围需重新核对授权。不要把普通阶段切换做成反复审批。
- 用户说“暂停/我要用电脑”，先停止后续桌面输入、释放已按住的键/按钮，再报告安全停止点。明确只暂停桌面时可继续已授权后台工作并通知；明确暂停/停止整个任务时不继续测试。恢复共享桌面须有用户恢复指示或约定的明确条件，不能靠等一段时间猜测。

## 有限操作批次

每批以一个可观察业务步骤或少量相关用例为界，不把所有坐标点击一次性投递给长时间无人观察的脚本。

1. 核实窗口、PID + 启动时间（或同等实例身份）、文档/布局/编辑状态、位置/DPI和当前输入焦点。默认用自有测试实例及副本；用户明确指定其当前实例时仅操作授权副本，不关其软件。
2. 优先使用有语义的控件定位与状态等待；CAD 画布点选可结合坐标转换和捕捉，但必须观察当前视图、命令提示和选择反馈。控件不可用、被遮挡或状态不符时不强行点击。
3. 输入前后核对状态；未知弹窗、失焦、用户插入操作、文档切换、超时或崩溃时立即取消后续输入。驱动应有超时/取消检查；不具备这些能力时采用可逐步观察的工具，不宣称已实现失焦保护。
4. 保留失败图和实际状态，定位前不重复投递整批操作。可在原因明确后有界重试，保留第一次失败；结果不稳定记为待解决，不能选最后一张成功图隐藏过程。

隐藏窗口、另一显示器、Windows 虚拟桌面或 UIA 不是输入隔离。共享桌面实操期间不能承诺用户可同时自由使用鼠标键盘；需要并行办公时，程序和驱动应处于已授权的独立测试机/虚拟机中，并核验其代表性。

## 阶段通知

简短说明“当前阶段；已完成/剩余；下一步；是否占用桌面”。每次方式切换前和接管/释放时都发消息；长阶段中也持续报告有效进展，不只将通知写入文件。例：

> 进入实操阶段：预检通过，接下来在测试副本验证宽度、深度和完整组合共 4 组，期间占用鼠标键盘。可随时让我暂停。

> 桌面已释放：4 组完成，其中 1 组结果缺失。现在转后台核对对象与深度，随后说明原因和需要复测的范围。

恢复任务先读本轮记录，核对输入/构建/配置、实例是否仍存在、桌面约定是否仍适用；不要仅凭旧 PID 继续点击。构建或源数据改变时建立新 run 并关联旧记录。

技能本身不安装常驻钩子、不轮询监控用户、不创建定时任务。这里只定义执行纪律；操作系统级隔离与驱动级中止机制需实际工具支持。

## 可复用输入适配器

`scripts/desktop_guard.py` 可被 Python 驱动导入，也可作为 CLI 使用；仅在显式实操入口调用。manifest 由本轮启动器写入 pid、start_ticks（.NET UTC ticks）、root_hwnd，可加 allowed_hwnds（已观察并批准的本应用顶层窗口）及 title_contains。默认只接受根窗口，未知同进程窗口也不放行；不能把任意同进程窗口全部列入允许名单。

每个字符、按键组合或点击前检查本轮 run.json 的 desktop/desktop 状态、PID与启动时间、窗口归属、根窗启用状态、是否最小化、前台窗口和可选标题。点击另核对坐标下的实际窗口归属；按键/鼠标抬起放在 finally 中。`acquire` 只在已通知接管或恢复时显式执行，可恢复已核实的最小化目标，不作为失焦后的重试动作。暂停时先停止输入，再记录 paused；恢复先获得依据、通知并记录，再显式接管。

适配器不理解 CAD 当前命令、图纸、布局、选点阶段或任意控件状态，项目驱动仍须检查这些前提。轮询式原子检查存在检查与输入之间的竞态，不能识别用户在同一窗口内的所有输入；不提供操作系统隔离，也不授权操作任何进程。现有驱动不必迁移，但只有实际演练过停止路径后才能声明通过。

CLI 检测到停止条件后把当前运行保持为 paused，并在 `input_stops` 写原因；后续命令不能直接 acquire。它不会伪造聊天通知，执行者仍须立即通知并用 session 记录 paused 事件，再按已有恢复依据处理。直接导入 Python 类的驱动在捕获 `InputStopped` 时调用 `latch_stop` 或提供等效保持机制；UIA定位/超时等外层错误也要停止整批依赖操作。

可选真实窗口演练入口为 `scripts/tests/run_desktop_probe.py --allow-desktop --output <新目录>`，使用自有 WinForms 测试窗及临时文件，显式占用共享桌面。它验证驱动机制，不是业务项目验收，模拟暂停不冒称用户亲自发过暂停指令。

`scripts/windows_uia.ps1` 是可选的 Windows UIA 定位与真实输入桥接，不是任意软件的现成测试器。Inspect/Locate/History 只读，写入动作要求显式 `-AllowDesktopInput`。项目适配器提供目标面板和 AutomationId；同名控件要限定类型，例如 `checkbox:启用:0`，不能把文字子元素计入复选框序号。生成前读取实际参数与勾选状态，不按点击次数推断设置成功。CAD Command 入口要求 manifest 中提供已观察的 `command_input_id`，不使用固定屏幕偏移。浮动命令窗口需核实后单独加入允许名单。

跨 Windows PowerShell / 原生命令传递含引号、中文或换行的文本时，使用 UTF-8 Base64 参数 `-ValueBase64`；桥接向输入器传 `--value-base64=`。这只是文本传输，实际键盘输入仍由 guard 逐步检查。先用无业务数据窗口核对原文往返，不能仅凭脚本退出码判断 CAD 收到的命令。

出现已知启动提示时先观察并核实窗口身份，只处理任务范围内的明确提示；未知弹窗仍停下。关闭提示后重新核对根窗启用、焦点和当前命令，确认后才记录恢复。输入驱动或加载失败时保留原日志，停止依赖操作，不能提前写“已恢复/已加载”。
