# 测试方法与工具选择

## 覆盖分层

| 层次 | 验证内容 | 对办公桌面的要求 |
|---|---|---|
| 算法与业务单元 | 正常、边界、异常、数值误差、幂等性、数据转换 | 通常无需窗口 |
| 真实服务或宿主 | 命令、存储、事务、插件加载、保存重开、原生撤销 | 选官方 CLI/API/无界面宿主；核查实际启动行为 |
| 控件与窗口集成 | 绑定、事件、对话框、命令路由 | 取决于框架和控件；单列入口，先验证是否抢焦点 |
| 真实输入与视觉 | 点击命中、快捷键、拖拽、捕捉、DPI、遮挡、焦点、实际渲染 | 使用独立测试机或虚拟机可与用户办公并行；否则安排明确的桌面占用时段 |

只调用按钮处理函数只能证明该函数路径。通过数据库检查只能证明相应数据条件。导出图像后还需实际查看或用独立指标比较，才能支持视觉结论。涉及真实 GPU、设备驱动或硬件授权时，应核对隔离环境是否能代表用户环境。

## 在现有项目中落地

保留现有解决方案与业务项目。把调度脚本、测试夹具、断言和报告放进已有验证工程；缺乏此结构时再建立清晰的验证目录。在已有 README 写明默认后台入口、桌面入口、所需环境及未测范围，不强制另建一套框架。

默认入口不得隐式转向完整 GUI 或屏幕驱动。屏幕入口使用显式启用参数，指向本轮创建的测试实例，核对 PID、启动时间或相应进程身份；COM/UIA 返回的实例也要与目标匹配。不要任取同名进程或借用用户正在工作的文档。

选择开源工具时按技术栈和现有依赖判断：

- .NET 单元与集成测试可用 [NUnit](https://github.com/nunit/nunit) 等成熟框架；已有断言有效时无需仅为形式迁移。
- Windows 控件测试可评估 [FlaUI](https://github.com/FlaUI/FlaUI)（UIA2/UIA3）。先实测自定义绘图控件、权限和焦点行为，不能据 UIA 名称承诺任意应用后台操作。
- 跨工具报告可参照 [JUnit XML 结构说明](https://github.com/testmoapp/junitxml)，分别表达 failure、error、skipped；团队已有报告格式时优先兼容。
- AutoCAD 真实无界面宿主参考 [AcCoreConsole 示例](https://github.com/MadhukarMoogala/aps-da-for-autocad)，具体适用条件见 CAD 示例。

这些来源的 README 已在本地 CAD 实践中于 2026-10-27 查阅，形成了分层和报告设计；不是框架已集成的声明。后续真正引入依赖前，再查其当前官方文档、版本、维护状态、许可证、平台支持和与项目框架的兼容性。比较相关选项和采用理由，不将搜索排名、星数或摘要当成质量与覆盖保证。

## 结果和资源

- 每轮唯一目录、独立环境和临时数据；记录输入指纹、提交及工作区改动、程序集/构建产物指纹、启动参数、工具版本、开始结束时间、各步骤状态。不能只记提交号而漏掉未提交改动。
- 输入和产物发生变化后，先判断受影响套件，补必要验证；历史报告需要重新匹配指纹和测试配置。没有相应指纹时不要声称证明了当前代码。
- 同时检查退出码、标准输出/错误及结构化报告。报告缺失、截断、重复终止标志、零断言、计数不符、失败断言、超时或资源超限均不是通过。空测试套件和主动跳过须明确记录为 NotRun/skipped。
- 采用 Passed、Failed、NotRun，报告失败原因与未测理由。执行器自身错误应保留为错误信息，汇总不能仍为 Passed。测试名称/参数组合应可唯一识别，报告总数应可核对。
- 优先串行、低优先级、可配置的步骤超时及内存保留。启动下一步骤前检查资源；缺资源则停止或拆分套件，不能以关闭办公程序腾资源。共享构建目录需要锁或独立输出；最终校验产物没有被其他构建替换。
- 调度器改动需验证失败传播、超时、环境隔离、报告拒收及清理边界。只增加与实际风险相关的检查，不为每个简单可逆编辑建立镜像测试。
- Windows PowerShell 5.1 的 `Get-Content` 字符串可能携带 Provider 扩展属性，直接 JSON 序列化会膨胀；需要纯文本报告时使用 `[IO.File]::ReadAllText` 或 `ReadAllLines`，并验证实际支持的 PowerShell 版本。

若软件完全没有可用的无界面接口，不强行宣称“全后台”。可以先提取可独立验证的业务逻辑，其余桌面任务在隔离环境执行，并保留端到端交互验收。
