# 功能完成后同步 GitHub

默认GitHub用户为 **GeistCber**。每个完成节点询问一次，用户选择上传后自动完成提交和同步。技能本身不会创建定时任务、后台监视或应用事件钩子；由用户的全局AGENTS.md完成规则调用。

## 完成节点与选择

先完成用户要求的功能、必要验证及可查看的改动。确认目标项目实际仓库路径，检查工作区、暂存内容、当前分支、upstream、remote及未推送提交，列明本次将同步的范围。不要把当前会话默认目录误当成用户所指项目。

项目有本次改动或未推送提交时，在最终完成答复前，用`functions.request_user_input_async`呈现一次选项，例如：

> 本次功能已完成并验证通过。是否上传到 GitHub？
> 目标：GeistCber/GumingLighting，分支 main；内容：取消引线加粗及对应验证说明。
>
> - 上传到 GitHub
> - 暂不上传

没有弹窗工具时直接用文本询问，不能声称已经弹出。未收到回复、预选选项或超时均不构成上传授权。用户选否就交付已完成结果，不反复询问同一节点。纯问答、只读检查、进度更新、尚未完成或验证失败的工作不触发。没有新改动且没有未推送提交时说明已同步，不弹空操作。

用户已明确要求本次上传，或本节点已选择“上传”，直接执行，不再询问提交、推送或创建默认私有仓库的许可；用户明确本次不上传则跳过。此前一次“是”不自动覆盖下一次功能完成节点。

如果执行本技能创建本身也需要询问上传，先完成安装和验证，再说明上传仅包含本技能文件，建议目标为GeistCber/codex-skills私有仓库；不要把全局配置或其他技能整体上传，也不要塞进无关业务仓库。

## 用户选择上传后

1. **确认范围。** 优先复用项目现有仓库和远程，不改变已有remote地址、可见性或分支约定。只提交本次项目相关改动，保留无关改动及他人暂存内容；混合修改时按文件或片段划定范围。不要无条件执行`git add --all`。
2. **首次建仓。** 项目没有仓库时初始化main；默认在GeistCber下以项目名创建私有仓库。检查同名远程是否存在，存在时先查看内容和权限，不能覆盖已有历史。只有确实缺少目标信息或存在冲突才集中问一次。技能创建上传默认使用独立codex-skills仓库，仅复制本技能文件后建仓。
3. **准备可用项目。** 需要时补.gitignore，排除缓存、构建目录、CAD锁/自动备份、临时日志、本机配置和凭据。源码、必要资源、用户需要的示例及验证记录正常提交。检查仓库外的实际编译依赖，必要时随项目纳入并注明来源，不上传宿主SDK；保持默认启动入口可用。已有项目不为同步Git而擅自重构业务。
4. **认证与连接。** 复用已有有效凭据。Windows上gh登录失效时，先尝试Git Credential Manager中GeistCber的有效凭据，再考虑人工登录。命令行直连失败时，使用本机已配置的代理，仅对当前进程生效。优先用下方脚本；不要读取并打印凭据，或让用户把token发到聊天。
5. **提交与推送。** 检查实际差异、暂存内容和明显凭据/大文件问题；生成准确提交说明并提交本次改动，再普通推送至当前分支或约定upstream。没有新文件改动而有未推送提交时直接推送。禁止强推、清理用户未提交内容、自动改写历史或自动解决远程分叉。推送若因新远程提交被拒，先fetch检查，只有符合项目约定且不影响用户历史时才整合。
6. **核验。** 比较本地HEAD与目标远程分支的提交SHA，核对仓库地址、可见性及工作区状态。只有SHA一致才报告同步完成；若存在本次范围外的未提交/未推送内容，应准确说明，不能宣称整个仓库干净。

远程或认证异常先检查实际结果，避免重复创建仓库或重复提交。同一操作恢复连接后至多重试一次；需要浏览器登录时明确给出原因和设备验证码，等待用户完成，不循环催促。无法恢复时保留本地结果并明确尚未上传。

## Windows 连接助手

使用[脚本](scripts/github-session.ps1)为单次gh/git调用设置临时代理、复用有效凭据并验证登录账号。它不自行提交、不创建仓库、不存储token，也不修改全局Git/代理配置。上传操作仍必须满足上面的用户选择。

```powershell
$helper='C:\Users\Laptop\.codex\skills\github-sync-on-complete\scripts\github-session.ps1'
& $helper -Tool gh -Arguments @('api','user','--jq','.login')
& $helper -Tool gh -Arguments @('repo','view','GeistCber/GumingLighting','--json','url,visibility,defaultBranchRef')
& $helper -Tool git -Arguments @('-C','D:\project\GumingLighting','ls-remote','origin','refs/heads/main')
```

首次创建仓库的调用应在本地提交已准备好、确认用户选择上传后执行：

```powershell
& $helper -Tool gh -Arguments @('repo','create','GeistCber/项目名','--private','--source','项目绝对路径','--remote','origin','--push')
```

不要用脚本调用凭据导出命令。确需另一个账号时先取得用户明确指示，再设置`-ExpectedLogin`；不自动切换到偶然发现的其他账户。

## 最终反馈

用中文简洁给出仓库链接、分支、短提交号和同步状态；首次建仓补充私有可见性。验证只报告本次真实执行的范围。不推送时说明本次暂未上传；失败时指出卡点、本地提交状态和接续所需的一步操作。
